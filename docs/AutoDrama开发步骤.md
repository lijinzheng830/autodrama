## 约束规则（开发纪律）

- **规则1：指令必须写死，不给发挥空间**。Kimi只能执行用户明确指定的修改，不得自行添加未提及的功能（如额外IPC通道、未要求的UI组件等）。如需扩展必须先征得用户同意。
- **规则2：改前先读**。修改任何文件前必须先读取该文件完整内容，理解上下文后再动手。
- **规则3：最小改动原则**。只改实现目标所必需的文件和代码行，不重构无关代码。
- **规则4：改后验证**。每次修改后必须 `npm run build` 通过，有测试的跑测试。
- **规则5：提交前diff**。提交前必须 `git diff` 确认改动范围正确，无意外修改。
- **规则6：回滚机制**。如发现Kimi改乱了代码，立即 `git reset --hard` 回滚到上一个稳定commit，重新给指令，不尝试在错误基础上修补。
