## 关键坑位

### 1. `ELECTRON_RUN_AS_NODE=1` 导致 Electron 初始化失败

**现象**: `require('electron')` 返回字符串（二进制路径）而非 Electron API；`process.type` 为 `undefined`

**原因**: 环境变量 `ELECTRON_RUN_AS_NODE=1` 让 Electron 以纯 Node.js 模式运行

**修复**: `package.json` dev 脚本前加 `ELECTRON_RUN_AS_NODE=` 覆盖：
```json
"dev": "ELECTRON_RUN_AS_NODE= electron-vite dev"
```

### 2. Electron 二进制下载失败

**现象**: `npm install electron` 后 `dist/` 目录只有 `LICENSES.chromium.html`，无 `electron.exe`

**原因**: GitHub 下载超时（网络限制）

**修复**: 
- 使用国内镜像: `ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/" npm install electron`
- 或手动从缓存提取: `unzip electron-v33.4.2-win32-x64.zip -d node_modules/electron/dist/`

### 3. DeepSeek API 返回 markdown 而非 JSON

**现象**: AI 返回详细的分镜 markdown 文档，无法提取 JSON

**原因**: 
- prompt 中提到"标准分镜描述模板"导致模型输出模板而非 JSON
- temperature 0.7 太高，输出不稳定

**修复**:
- `response_format: { type: 'json_object' }` 强制 JSON 模式
- 每个 prompt 末尾加"请以 JSON 格式返回"
- temperature 降到 0.1
- `cleanJSON` 函数兜底处理

### 4. API Key 检查失败（`api_key_${provider}` 为空）

**现象**: 点"一键生成分镜"提示"请先配置 API Key"

**原因**: `handleParseSubmit` 只检查 `settings` 表中的 `api_key_${provider}` 键，但 API Key 存储在 `providers` JSON 的 `apiKey` 字段中

**修复**: `getSetting('api_key_${provider}')` 找不到时，fallback 到从 `providers` JSON 中查找对应供应商的 `apiKey`

### 5. `loadProviderModels()` 和 `loadParseModel()` 竞态

**现象**: 语言模型下拉为空

**原因**: 两个 async 函数同时启动但未 await，`loadParseModel` 可能在 `loadProviderModels` 完成前执行

**修复**: `openParseDialog` 改为 `async function`，两个调用前加 `await`

### 6. GitHub HTTPS 443 被墙

**现象**: `git push` timeout，`fatal: unable to access`

**修复**: 使用带 token 的 HTTPS URL：
```
https://username:token@github.com/user/repo.git
```
或使用 SSH（需先生成 key 并添加到 GitHub）

## SQLite 常用查询

```sql
-- 查看所有设置
SELECT * FROM settings ORDER BY key;

-- 统计项目数据
SELECT 
  (SELECT COUNT(*) FROM characters WHERE project_id='<id>') as chars,
  (SELECT COUNT(*) FROM scenes WHERE project_id='<id>') as scenes,
  (SELECT COUNT(*) FROM props WHERE project_id='<id>') as props,
  (SELECT COUNT(*) FROM chapters WHERE project_id='<id>') as chapters,
  (SELECT COUNT(*) FROM shots s JOIN chapters c ON s.chapter_id=c.id WHERE c.project_id='<id>') as shots;

-- 查看生成任务
SELECT id, type, purpose, status, model, channel, error_message, created_at
FROM generation_tasks WHERE project_id='<id>' ORDER BY created_at DESC LIMIT 20;
```

## AI Debug

AI 调用失败时，检查：
1. 数据库 provider 设置是否正确: `SELECT * FROM settings WHERE key='provider'`
2. providers JSON 中的 apiKey: `SELECT * FROM settings WHERE key='providers'`
3. 模型路由: `SELECT * FROM settings WHERE key='model_routes'`
4. JSON 提取失败日志: `C:\Users\Administrator\ai_response_debug.log`（最后一次失败的 AI 原始返回）
5. 主进程 console 输出: electron-vite 终端
