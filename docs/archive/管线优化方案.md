# 无限创意 管线优化方案

## 一、总体评估

当前8条管线覆盖了从剧本到视频的完整链路，SD2.0 模板体系基本成型。核心问题集中在三类：

| 类别 | 数量 | 典型问题 |
|------|------|---------|
| 硬编码残留 | 5处 | 年代检测、翻译、脚本审查、生图fallback — 不走DB模板 |
| 死模板 | 10个 | v2润色×6、视频引导×4 — 在DB但无代码调用 |
| SD2.0适配不彻底 | 4处 | 故事板prompt写死在代码里、资产描述缺权重语法、视频参考图不传故事板 |

---

## 二、逐管线诊断

### 管线1：剧本解析 ★★★

**现状**：SD2.0导演级模板，v33版本，多章节支持，内容安全过滤。整体较好。

**问题**：
1. 输出仍包含 `first_frame_prompt`/`last_frame_prompt` 字段（已废弃），浪费token
2. 章节分段缺少明确规则——"长剧本≥800字→多段"太粗糙，应改为按场景转换/关键事件切分
3. 没有对每章景别配比的校验——可能输出8个中景+1个全景，不符合SD2.0

**优化**：
- 删掉输出格式中的首尾帧字段，节省~20% token
- 分段改为"场景转换即分段"规则，更精准
- 输出格式加景别配比自检要求

---

### 管线2：资产提取 ★★

**现状**：结构化8字段/6字段，模糊匹配+自动创建。

**问题**：
1. 单独一次LLM调用，解析+提取两次调用增加延迟和成本
2. 描述是纯文本，缺SD2.0权重语法——如 `(almond-shaped eyes:1.2)` 比 `almond-shaped eyes` 对生图模型约束更强
3. 角色描述和场景描述没有交叉引用——角色的光影应该匹配场景的光影

**优化**：
- 方案A（低成本）：在资产描述生成后，代码层自动注入权重括号
- 方案B（彻底）：合并解析+提取为一次LLM调用，输出完整生产包

---

### 管线3：年代检测 ★

**现状**：硬编码prompt，功能正常。

**问题**：不在DB模板体系，用户不可编辑。没有年代→画风关键词映射。

**优化**：
- 迁入DB模板（usage: `era_detect`）
- 年代检测结果自动注入生图管线——古代的负向词加 `modern objects, neon lights`，未来的加 `ancient architecture, traditional clothing`

---

### 管线4-6：角色/场景/道具生图 ★★

**现状**：DB模板驱动，wubianjie API，source_url保存。功能稳定。

**问题**：
1. 模板缺少SD2.0权重语法——角色模板里 `facial features consistent` 不如 `(facial features consistent with reference:1.3)`
2. 场景图生成时没有传入角色图作为尺度参考
3. 道具图没有关联到角色/场景的手持关系

**优化**：
- 模板加入权重语法
- 场景生图时附带角色 reference_url（帮助模型理解人景比例）
- 道具生图时附带角色描述（如"剑被角色握在右手"）

---

### 管线7：九宫格故事板 ★★★★★ （最大问题）

**现状**：prompt完全由代码动态构建，不走DB模板。用户无法编辑故事板prompt。

**问题**：
1. **prompt写死在代码里**——跟其他7条管线不一致，用户看不到也改不了
2. **没有传参考图**——角色/场景 source_url 收集了但只用于日志，没传给API
3. **SD2.0权重语法缺失**——`(strict 3x3 grid:1.3)` 只是开头一句
4. **v1-07-grid-storyboard.md 模板文件已废弃**——代码完全不读它
5. **每格描述太长**——一个格描述可能100+词，9格prompt轻松超2000词，稀释了格式化约束

**优化方案**：

```
方案：Prompt 模板化 + 参考图注入 + 描述精简

结构：
┌─────────────────────────────────┐
│ 1. 格式+画风 （来自DB模板）      │
│ 2. 全局一致性约束（来自DB模板）   │
│ 3. 参考图调用（代码动态注入）     │  ← 新增：角色/场景 source_url
│ 4. 9格分镜正文（代码动态构建）    │  ← 改为：每格≤40词精简版
│ 5. 负向词+品质（来自DB模板）      │
└─────────────────────────────────┘
```

具体改动：
- 重写 `v1-07-grid-storyboard.md`，分段式模板（header/body/footer）
- header（格式+风格+一致性）和 footer（负向词+品质）从模板读
- body（每格描述）由代码构建，但每格描述从 shot 数据提取并精简到 ≤40 英文词
- 参考图注入：`Reference @角色图1, @场景图1, ...`
- 约束权重化：`(same character face and costume across all 9 frames:1.3)`

---

### 管线8：视频生成 ★★★

**现状**：kwvideo-v2-ref 可用，DB模板驱动，source_url参考图。

**问题**：
1. 视频prompt没有参考故事板格——生成的故事板和生成的视频视觉不连贯
2. `grid_to_video` 模板段存在但从不使用
3. 视频生成时机没有经过故事板确认——可能故事板质量差就进了视频
4. `segmented_first/segmented_second` 分段生成模板未启用

**优化**：
- 视频prompt中注入对应故事板格的内容描述（保证画面连贯）
- 启用 `grid_to_video`：如果该镜有故事板，用故事板图作为视频参考
- 视频生成前检查故事板状态，无故事板时提醒先生成

## 三、跨管线优化

### 优化1：硬编码迁入DB模板

| 硬编码 | 当前文件 | 优化 |
|--------|---------|------|
| 年代检测prompt | ai.ts:675 | → DB模板 `usage: era_detect` |
| 翻译prompt | ai.ts:1030 | → DB模板 `usage: translate` |
| 脚本审查prompt | scriptReviewer.ts:521-626 | → DB模板 `usage: script_review` |
| 生图fallback prompt | imageGenerator.ts:193-234 | → 删掉，模板加载失败直接报错 |
| 故事板prompt | imageGenerator.ts:1224-1261 | → `v1-07-grid-storyboard.md` |

### 优化2：死模板清理

10个无代码调用的模板 → 从DB注册表删掉或标记为disabled。减少Settings页面的噪音。

### 优化3：SD2.0权重语法统一注入

在所有生图/生视频模板中统一使用 `(关键词:数值)` 格式：
- 格式约束：`:1.3`
- 角色一致性：`:1.25-1.3`
- 场景一致性：`:1.25`
- 局部细节：`:0.8-1.0`

### 优化4：管线间数据贯通

```
当前（孤岛）:
  解析 → 资产 → 生图 → 故事板 → 视频
  (各管各的，没有反馈)

优化后（贯通）:
  解析 ──→ 资产 ──→ 生图 ──→ 故事板 ──→ 视频
    ↑        ↑        ↑         ↑         ↑
    └────────┴────────┴─────────┴── source_url 贯穿 ──┘
    └────────┴── 年代/风格 贯穿 ──────────────┘
```
